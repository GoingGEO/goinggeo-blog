网站速度直接影响 GEO 效果——页面越慢，AI 爬虫抓取同样多的内容就要花更多资源，结果往往是“抓不全、索引不全”，你的内容再好 AI 也读不到。Google 用 Core Web Vitals（LCP、INP、CLS 三个指标）衡量体验，AI 引擎虽不公开标准，但逻辑一致：慢站不值得多抓。本文用非技术语言讲清三个指标、外贸站常见速度拖累，以及不改代码就能提速的 3 个方法。

Core Web Vitals 是 Google 提出的三项用户体验指标：LCP（最大内容绘制，衡量加载速度）、INP（交互延迟，衡量响应）、CLS（累积布局偏移，衡量视觉稳定性）。

## LCP / INP / CLS，用大白话讲

- **LCP（最大内容绘制）**：页面“主要东西”显示出来要多久。超过 2.5 秒算慢。对外贸站来说，主图、首屏产品图往往是 LCP 元素。
- **INP（交互延迟）**：你点一下、滚一下，页面多久才反应。超过 200 毫秒算差。
- **CLS（布局偏移）**：页面加载时元素是不是“乱跳”。图片没留尺寸位，文字就被挤下去，这就是 CLS 差，超过 0.1 算不合格。

## 为什么慢站伤 GEO

AI 爬虫（以及 Googlebot）每天给你网站的“抓取预算”是有限的。页面慢，爬虫在单位时间里能抓的页面就少。如果你的站有 50 篇文章，但每页要 5 秒才加载完，爬虫可能只抓了 10 篇就走了——剩下 40 篇根本没进索引，自然不可能被 AI 引用。

所以“速度”不是锦上添花，而是“内容能不能被读到”的前提。想先知道 AI 现在怎么看你的站，可以读 [AI 可见性审计](/posts/ai-visibility-audit-for-foreign-trade/)。

## 外贸网站常见的 4 个速度拖累

1. **未压缩的大图**：产品图动辄几 MB，是最常见拖累。
2. **没有用 CDN**：图片和静态资源从单一服务器跨洋传输，海外访问尤其慢。
3. **第三方脚本过多**：聊天插件、统计、再营销代码一堆，拖慢加载。
4. **未启用缓存和压缩**：HTML/CSS/JS 没压缩，重复传输。

## 不改代码就能提速的 3 个方法

1. **压缩图片到合理尺寸 + 转 WebP/AVIF**：用工具把产品图压到 100KB 以内，格式换成 WebP。这是最省力、见效最快的一步。
2. **上 CDN**：让图片和静态资源就近分发，海外买家和爬虫都能快速拿到。AstroPaper 这类静态站部署到 Cloudflare Pages 等平台，CDN 基本是默认带上的。
3. **清理无用第三方脚本**：只保留必要的，能异步加载的异步加载。每个多余脚本都是速度税。

如果你用的是 AstroPaper，它本身是静态生成、默认就很轻量；只要图片别太夸张、部署到带 CDN 的平台，Core Web Vitals 通常轻松过关。等真要做更深入的技术优化，再考虑代码层面改动。

**Q：Core Web Vitals 和 GEO 到底有什么关系？**

A：关系在“抓取预算”。页面慢，AI 爬虫和 Googlebot 在单位时间能抓的页面就少，导致内容索引不全，再好的内容也进不了 AI 的答案。速度决定了你的内容“能不能被读到”。

**Q：LCP、INP、CLS 三个指标，哪个对 GEO 最关键？**

A：对内容型外贸站，LCP（加载速度）通常最关键，因为它直接决定爬虫能抓多少页。INP 和 CLS 影响的是真人体验和 Google 评分，间接影响可信度。

**Q：我完全不懂代码，能优化网站速度吗？**

A：能，而且大部分提速来自非代码动作：压缩图片、用 CDN、清理多余插件。这些在后台或部署平台就能操作，不碰代码。

**Q：AstroPaper 这类静态博客速度一般没问题吧？**

A：对，静态生成天然轻量。只要注意图片别太大、部署到带 CDN 的平台（如 Cloudflare Pages），Core Web Vitals 基本能轻松达标。

**Q：怎么查自己网站的 Core Web Vitals 分数？**

A：可以用 Google Search Console 的“核心网页指标”报告（基于真实用户数据），或用 PageSpeed Insights 测单页。两者都免费。

**Q：图片压缩会不会让产品图变模糊？**

A：合理压缩不会。把图压到 100KB 以内并转 WebP/AVIF，肉眼几乎无差别，但加载快几倍。关键是“尺寸合适”而非“拼命压”。

**Q：速度优化了，GEO 效果多久能看到？**

A：技术改动生效较快（几天到几周），但 GEO 效果体现取决于内容是否被更完整地抓取和索引。速度只是前提，不是充分条件，要配合内容质量。
