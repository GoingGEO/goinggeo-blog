# GoingGEO Blog → Anthropic OSS Scanner 提交指南

目标：把本仓库作为扫描目标，提交 PR 到 `anthropics/oss-scanner`，
免费拿一份 AI 辅助的依赖漏洞审计。

## 前置准备（本文件已就绪）
- ✅ `project.yaml` — 目标配置
- ✅ `Dockerfile` — 让扫描器解析依赖树
- ✅ `threat_model.md` — 威胁模型

## 提交步骤

```bash
# 1. Fork anthropics/oss-scanner 到你的 GitHub
#    （网页上点 Fork 即可）

# 2. 把本目录三个文件复制到 fork 的 targets/goinggeo-blog/
#    在 fork 的本地克隆里执行：
mkdir -p targets/goinggeo-blog
cp /path/to/goinggeo-blog/oss-scanner-submission/* targets/goinggeo-blog/

# 3. 提交并发 PR
git add targets/goinggeo-blog/
git commit -m "Add goinggeo-blog (AstroPaper static site) as a scan target"
git push origin main
#    到 GitHub 网页开 PR 到 anthropics/oss-scanner/main
```

## 提交前务必复核（避免 PR 被打回）

1. 打开 `anthropics/oss-scanner` 仓库的 `targets/` 目录，挑一个现有目标，
   对照它的 `project.yaml` 字段名调整我们的 `project.yaml`（schema 偶尔微调）。
2. 确认 `Dockerfile` 能在你的 fork 里 `docker build` 通过（本地有 docker 的话先试）。
3. PR 描述里贴上本目录 `threat_model.md` 的结论（"低风险静态站，主要审供应链"），
   能加快审核。

## 拿到结果后

- 结果会列出漏洞依赖（如有）。无高危即最佳结果。
- 建议顺势产出一篇 goinggeo 文章：
  《我们如何给自己的 GEO 站点做 AI 安全审计》——这是"经验独有、检索不到"的 GEO 弹药。
